# Проверка указателей в CLion

В проекте два запуска. Файлы реализаций указателей при обновлении тестов
не изменялись.

## All CTest

После изменения CMakeLists.txt нажми Reload CMake Project и запусти All CTest.
CTest запускает 92 проверки:

| Группа | Количество |
|---|---:|
| UnqPtr: перемещение, одиночные объекты и массивы | 28 |
| ShrdPtr: совместное владение, подтипизация и массивы | 27 |
| WeakPtr: наблюдение, lock, expired и массивы | 30 |
| Сопоставление поведения с шестью стандартными аналогами | 6 |
| Проверка удаления всех отслеживаемых объектов | 1 |

Стандартные аналоги: std::unique_ptr<T>, std::unique_ptr<T[]>,
std::shared_ptr<T>, std::shared_ptr<T[]>, std::weak_ptr<T> и std::weak_ptr<T[]>.
Их применение находится только в сравнительных тестах и измерениях.

Ожидаемый итог: «Тестов пройдено: 92/92», код завершения 0, без отчётов
AddressSanitizer и LeakSanitizer. В сводке CTest будет один успешно пройденный
запуск: 92 проверки выполняются внутри этой программы.

ENABLE_SANITIZERS должен оставаться ON. Для homeworkone_3 подключены
-fsanitize=address,leak при компиляции и компоновке.
CTest сам задаёт ASAN_OPTIONS=detect_leaks=1. При прямом запуске через Run
эту переменную следует добавить в Run / Edit Configurations.
Запускать Run или All CTest, не Debug: LeakSanitizer не работает под ptrace.

## pointer_benchmark

Выбери pointer_benchmark в списке конфигураций CLion и нажми Run.
Этот исполняемый файл собирается с -O2 и без санитайзеров.
Санитайзеры остаются включёнными у функциональных тестов.

Вывод разделён на пять самостоятельных сравнений:

1. UnqPtr / std::unique_ptr.
2. UnqPtr / raw.
3. ShrdPtr / std::shared_ptr.
4. ShrdPtr / raw.
5. WeakPtr / std::weak_ptr.

У каждой пары свои таблицы и графики по памяти и времени, отдельно для
обычных объектов и массивов. N меняется от 100 до 1000000.
У каждой временной таблицы указано, что означает N и какие действия входят
в замер. Для массива это либо длина одного массива, либо количество
владельцев/наблюдателей массива из одного элемента.

Время: создание, чтение и удаление; для unique со стандартным аналогом —
дополнительно перемещение; для shared со стандартным аналогом — создание
совладельцев; для weak — создание наблюдателей и lock() живых данных.
У сырых указателей освобождение вручную входит в замер.
Счётчик владельцев для raw не имитируется.

Для каждой строки выполняется прогрев, затем пять измерений каждой стороны.
Результат — медиана: среднее по порядку из пяти отсортированных значений.
Порядок сторон чередуется. Это уменьшает влияние случайных задержек,
но не устраняет влияние системы и оптимизаций компилятора.
Графики используют значения из таблиц и имеют отдельный масштаб.
Очень короткий положительный результат получает минимум один символ #.

## Что означает отчёт памяти

Размеры N самих указателей рассчитываются через sizeof и сопоставляются
для всех пяти пар. Здесь не учтены данные и динамические служебные блоки.
Для unique дополнительно сопоставляется расчёт с данными; для shared / raw
сопоставляется расчёт с данными и блоками нашей реализации.
У каждой пары массивов показан размер именно специализации T[].

Размеры блоков нашей реализации приведены отдельно. Внутренний блок STL
не угадывается, поэтому таблицы размеров shared/weak не обозначают полную
память STL. Не учитываются накладные расходы аллокатора, служебные данные
выделения массивов и санитайзеров. Это расчёт, а не измерение RSS процесса.

## Ограничения реализации

Указатели учебные и однопоточные. У WeakPtr одиночного объекта lock() создаёт
вспомогательный объект доступа, поэтому может выделять память и выбрасывать
исключение. Проверки сравнивают обычное однопоточное поведение с STL,
а не заявляют полную совместимость всех гарантий стандартной библиотеки.

## Проверка обновления

Проект собран без предупреждений. Функциональная программа прошла 92/92
с AddressSanitizer. Нагрузочные сценарии до миллиона завершились с верными
контрольными суммами.

Поэтому полный запуск с проверкой утечек нужно повторить через All CTest
непосредственно в CLion; флаг detect_leaks=1 в CMake сохранён.
